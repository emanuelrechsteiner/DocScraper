## Vision

Parsify transforms DocScraper — a Python documentation scraping and post-processing toolkit — into a production-grade REST API service. Developers will be able to scrape, clean, chunk, and classify documentation through simple API calls instead of running Python scripts locally. The service targets teams building RAG pipelines, knowledge bases, and AI-powered documentation search who need reliable, scalable document processing without managing infrastructure.

---

## Core Features

### F000 — Codebase Cleanup (Audit Fixes)

**Description:** Fix all critical bugs, stale tests, code quality issues, and documentation errors identified by the comprehensive audit.

**User Value:** A stable, tested, correctly-documented foundation is required before building any API layer on top.

**Technical Scope:** Fix hardcoded paths, bare excepts, stale test assertions, missing type hints, logging anti-patterns, class name collisions, cost calculation bugs, and documentation factual errors.

### F001 — REST API Layer

**Description:** A FastAPI-based REST API wrapping the existing scraping and post-processing engines with proper authentication, input validation, and async job management.

**User Value:** Developers can scrape and process documentation via HTTP API calls instead of running Python scripts, enabling integration into CI/CD pipelines and automated workflows.

**Technical Scope:** FastAPI application, Pydantic request/response models, API key authentication, async job queue for long-running scrape operations, webhook callbacks for job completion.

### F002 — Billing & Usage Management

**Description:** Rate limiting, usage tracking, and Stripe-based subscription billing with tiered plans (free, pro, enterprise).

**User Value:** Self-service billing with transparent usage tracking. Free tier for evaluation, paid tiers for production workloads.

**Technical Scope:** Per-key rate limiting (Redis-backed), usage metering, Stripe subscription integration, webhook handling for payment events, billing dashboard API endpoints.

### F003 — Production Infrastructure

**Description:** PostgreSQL database, CI/CD pipeline, Docker containerization, and production deployment.

**User Value:** Reliable, scalable service with automated testing and deployment — no manual intervention needed.

**Technical Scope:** PostgreSQL schema (jobs, users, API keys, usage), Alembic migrations, GitHub Actions CI/CD, Docker multi-stage builds, deployment to Railway/Render.

### F004 — Documentation & Landing Page

**Description:** API documentation site, landing page with pricing, and integration guides.

**User Value:** Developers can discover, evaluate, and integrate Parsify with clear documentation and examples.

**Technical Scope:** OpenAPI/Swagger auto-generated docs, MkDocs documentation site, landing page, code examples in Python/JS/curl.

### F005 — SDK & Launch

**Description:** Python and JavaScript SDK wrappers for the REST API, plus public launch activities.

**User Value:** Native language SDK makes integration trivial — `pip install parsify` or `npm install parsify`.

**Technical Scope:** Python SDK (auto-generated from OpenAPI), JavaScript/TypeScript SDK, PyPI/npm publishing, launch marketing.

## Technical Architecture Summary

| Layer | Technology | Rationale |
|-------|-----------|-----------|
| API Framework | FastAPI | Native async, auto OpenAPI docs, Pydantic validation — see ADR-001 |
| Database | PostgreSQL + SQLAlchemy | Relational data (users, jobs, billing), async support — see ADR-002 |
| Job Queue | ARQ (Redis-backed) | Lightweight async queue, native Python, good for long scrape jobs — see ADR-003 |
| Authentication | API Key (hashed) | Simple, stateless, per-key rate limiting — see ADR-004 |
| Rate Limiting | slowapi + Redis | Per-key limits, token bucket — see ADR-005 |
| Billing | Stripe | Industry standard, Python SDK, webhook support — see ADR-006 |
| Deployment | Railway | PostgreSQL + Redis included, Docker support, auto-deploy — see ADR-007 |
| Scraping Engine | crawl4ai + Playwright | Existing engine, proven, async — inherited |
| AI Classification | OpenAI API (GPT-4o) | Existing engine for document classification — inherited |

> Architecture decisions: see `ARCHITECTURE.md`

## Dependencies & Considerations

### Critical Dependencies

| Dependency | Type | Risk | Mitigation |
|------------|------|------|------------|
| OpenAI API | External | MEDIUM | Cache responses, implement fallback models |
| crawl4ai | Package | LOW | Pin version, fork if abandoned |
| Playwright | Package | LOW | Well-maintained by Microsoft |
| Stripe | External | LOW | Industry standard, test mode available |
| Redis | Infrastructure | LOW | Required for job queue + rate limiting |

### Risk Factors

| Risk | Severity | Probability | Mitigation |
|------|----------|-------------|------------|
| crawl4ai breaking changes | MEDIUM | LOW | Pin version, integration tests |
| OpenAI API cost spikes | HIGH | MEDIUM | Usage limits, cost tracking, caching |
| Playwright browser instability | MEDIUM | LOW | Retry logic, health checks |
| Stripe webhook reliability | LOW | LOW | Idempotent handlers, event replay |

## Research Findings Summary

> Full evaluation: `RESEARCH_FINDINGS.md`

| Domain | Decision | Confidence | Key Trade-off |
|--------|----------|------------|---------------|
| API Framework | FastAPI | HIGH | Best async support + auto docs, smaller ecosystem than Django |
| Database | PostgreSQL + SQLAlchemy | HIGH | Proven, async-capable ORM, steeper learning curve than SQLModel |
| Job Queue | ARQ | MEDIUM | Lightweight + async-native, less mature than Celery |
| Authentication | API Key (hashed) | HIGH | Simple for API service, no OAuth complexity needed initially |
| Rate Limiting | slowapi + Redis | HIGH | Standard approach, requires Redis dependency |
| Billing | Stripe | HIGH | Industry standard, excellent Python SDK |
| Deployment | Railway | MEDIUM | Easy setup, may need to migrate for scale |
| Testing | pytest + httpx | HIGH | Standard Python testing, great async support |
| Documentation | MkDocs | HIGH | Simple, Markdown-native, good theming |
